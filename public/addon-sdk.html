BossTunnel Addon SDK

Build an authorized media source once. Boss maps it into the canonical graph and exposes it through native Boss, Xtream and M3U outputs.

An addon is a hosted HTTP service, not uploaded executable code. Boss fetches a versioned descriptor at /addon.boss, then follows its extensionless catalogue, metadata and playback resource URLs. It never executes an author's JavaScript on the Boss server.

Metadata and playback are separate. Listing and searching must not generate stream URLs, contact playback resolvers, or start media downloads. Resolve an authorized HTTP resource only in the playback handler.

The SDK uses Node.js built-ins, with UTF-8 JSON as its HTTP data encoding. The native descriptor filename is addon.boss. The SDK publishes it as a downloadable UTF-8 JSON document with addonUrl, format, version, capabilities and resource URLs. It keeps /addon as a legacy alias. A .boss file is not executable code or a media container; never embed account passwords or permanent playback URLs. Private access links must be handled as secrets. App developers should use the App SDK guide.

Direct upstream playback contract

Addon handlers must return the exact authorized upstream URL, not a BOSS relay or a rewritten playlist. Playback flows Provider to Player. BOSS does not fetch video, remux, transcode, rewrite HLS or offer a proxy fallback. Preserve signed paths and queries exactly; do not insert credentials into the URL.

Return every available compatible choice with requiredHeaders, expiresAt (UTC milliseconds when known), resolution dimensions, codec, HDR, audio and languages. Use name and qualityLabel for quality such as 1080p or 4K UHD, and a separate source for provider details. Unknown quality must remain unknown. The author SDK adds delivery: direct and headerOrigin without contacting media.

Headers are visible to the authorized player and must be scoped to the resource origin. They are not hidden behind BOSS. Header-dependent resources require a capable player; ordinary Xtream/M3U redirects cannot deliver arbitrary headers and may return 422. Expose only authorized sources to trusted recipients. Never send credentials to unrelated origins, log private links, or claim BOSS revocation invalidates upstream links already issued.

Return an empty array for unavailable streams, never torrent or DRM resources. Keep metadata separate from playback lookup. Provider CORS, network reachability and IP-bound access must permit the actual player. Addon authors and players must reject unsupported media responses because BOSS does not probe video bytes. See the app SDK direct-playback contract for expiry, source selection, subtitles, EPG and full platform acceptance.

Files and deployment

  • boss-addon.mjs: reference HTTP server and validation.
  • addon-example.mjs: working one-item, authorized-media example.
  • addon-ecosystem.cjs: production PM2 configuration.

Place these files together. Use Node.js 20.12+ or 22. The example binds to 0.0.0.0:3000. Its public base URL must match the path your NGINX reverse proxy forwards.

export BOSS_PUBLIC_URL='https://your-addon.example'
export BOSS_MEDIA_URL='https://your-authorized-media.example/video.mp4'
export BOSS_ADDON_TOKEN='replace-with-a-long-random-secret'

npm install --no-save pm2
./node_modules/.bin/pm2 start addon-ecosystem.cjs
./node_modules/.bin/pm2 save

Set up PM2 startup for your Linux service user, terminate HTTPS at NGINX, and proxy to port 3000. Forward Host and X-Forwarded-Proto. The addon serves metadata and links only; do not configure a media relay. Behind Cloudflare, do not cache authenticated responses. Keep credentials out of access logs and backups readable only by the service owner.

The SDK example serves API metadata and playback links. It does not host or transcode the media itself. Configure an authorized media URL. Add https://your-addon.example/addon.boss to Boss using source type Boss addon; enter the matching access token when configured.

Handler contract

import { createBossAddon } from './boss-addon.mjs';

const server = createBossAddon({
  id: 'com.example.library',
  name: 'My library',
  baseUrl: process.env.BOSS_PUBLIC_URL,
  token: process.env.BOSS_ADDON_TOKEN,
  types: ['movie', 'series', 'episode']
}, {
  catalogue: async (query, { signal }) => ({
    items: await databasePage(query, signal), next: null
  }),
  search: async (query, { signal }) => ({
    items: await searchMetadata(query.search, query, signal),
    next: null, nextOffset: null
  }),
  media: async ({ id }, { signal }) => findMetadata(id, signal),
  playback: async ({ id }, { signal }) =>
    resolveAuthorizedHttpResources(id, signal)
});
server.listen(3000, '0.0.0.0');

The database and resolver functions above are supplied by the author. The downloadable example runs without those application-specific functions.

Every handler receives an AbortSignal. Respect it in database and HTTP work; the SDK signals cancellation on disconnect or after 15 seconds. Handlers must implement their own bounded concurrency and rate limiting for expensive upstream work. Catalogue pages cannot exceed the requested limit (maximum 200). Catalogue and metadata responses cannot exceed 8 MB. XMLTV guides stream one bounded programme at a time. Empty results return an empty array, not a fabricated item.

Capabilities are derived from supplied handlers. Optional resources are omitted. An optional guide handler enables EPG for channel addons. An optional catchup handler enables provider archives when channel, metadata and playback support are also present. Timeshift remains unsupported. Do not claim unsupported functionality.

// Optional guide handler for addons declaring the channel type.
// Match channelKey to the channel record's channel.epgId.
async function* guide({}, { signal }) {
  for await (const row of database.programmes({ signal })) {
    signal.throwIfAborted();
    yield { channelKey: row.channelId, title: row.title,
      description: row.description,
      startsAt: row.startMilliseconds, endsAt: row.endMilliseconds };
  }
}
// Supply this function as handlers.guide. The SDK exposes /guide as XMLTV.
// Titles: max 4096 characters; descriptions: max 65536; channel keys: max 256.
// Timestamps are integer UTC milliseconds; stop must be later than start.
// Respect cancellation and use bounded database pages, not a full guide array.

// Optional provider archive handler, supplied as handlers.catchup.
// The media handler must return this channel's positive channel.catchupDays.
async function catchup({ id, start, end }, { signal }) {
  return authorizedArchiveProvider.resolve({ id, start, end, signal });
}
// Return the same resource array as playback, or [] for an unavailable recording.
// UTC millisecond intervals: maximum 24 hours and within the channel's window.
// No live-stream fallback, torrent resources or invented recordings.

// Subtitle resources can declare their own headers and expiry too.
// { id: 'english', language: 'eng', url: 'https://authorized.example/subtitle',
//   requiredHeaders: { Authorization: 'Bearer subtitle-specific-token' },
//   expiresAt: 1900000000000 }
// The trusted player receives these headers and sends them only to the resource origin.

// Playback handler result: no torrent or DRM resources.
[
  { url: 'https://authorized.example/current-video.mp4',

Only supply verified stream attributes. Expiry is an absolute timestamp in milliseconds. The example timestamp illustrates the field, not a recommended permanent expiry. Return an empty array if no authorized stream is currently available. Do not expose server filesystem paths, unrelated credentials, or non-media sidecar files.

Catalogue-only addons and sources

Omit the playback handler to build a metadata-only addon. It can provide recent releases, genres, search and series metadata without promising playback. In a combined Boss library, a separate authorized identity-capable playback source can resolve those titles at play time.

Users may also add external compatible catalogue descriptors using Catalogue source. That mode imports metadata and explicitly disables playback from that source, even if the external provider advertises streams. It is separate from a native Boss addon.

Persist large catalogues in a database, return bounded pages, use stable cursors, deduplicate reliable external identities and ingest changes incrementally. Do not keep an entire large catalogue in a JavaScript array or replace one placeholder's title and ID whenever a user searches.

Required preset filters in compatible external catalogues are expanded into bounded feeds. Genre-filtered titles retain genre categories, and overlapping reliable identities deduplicate. Other-source adapters allow 64 preset values and combinations per catalogue; catalogue-only sources allow 256. Both are bounded to 256 feeds per source. Catalogue-only sources omit feeds needing required filters without preset values; other-source adapters reject them. Boss does not guess personalized filter values. Search-required feeds remain search-only. Adding a catalogue still does not guarantee a playable recording.

Displayed metadata comes from active sources in the connected library, ordered by source priority and then source ID. Genres combine those sources' current values, without case-only duplicates, up to 100 values. Unselected sources do not supply descriptive fields to the player. Canonical identities remain shared. Local text search indexes each source's current title and original title, restricted to active mappings in the connected library. Results retain the library's preferred display title even when another selected source's title matched. Renamed titles replace old index entries; historical aliases are not retained automatically.

Series, episodes and stable identity

Source IDs must remain stable across requests, refreshes and restarts. Supply IMDb, TMDB and TVDB identities only when reliable. Boss creates its own canonical UUIDs and persistent Xtream IDs; an author's local ID is a source identity, not a Boss database ID.

Declare series and episode types for television. Return series in the normal series catalogue. For catalogue({ type: 'episode', seriesId }), return that series' episodes with stable IDs, source seriesId, integer seasonNumber and episodeNumber. Boss retains the hierarchy and indexes episodes without resolving streams.

The same media graph is used by all output adapters. Boss-aware apps can use equivalent extended search through native Boss, Xtream or M3U discovery. Legacy players still have their protocol's limitations. See the app integration contract.

Security and authorization

  • Serve only sources the user is authorized to access. Respect authentication, subscriptions, licenses and DRM restrictions.
  • Use a long random addon token for private services. The SDK expects Authorization: Bearer token. Never ask an addon user for the Boss management token.
  • Use HTTPS. Keep source API resources on the configured origin. Boss forwards the source token only to that origin, not to another media host.
  • Never return magnets, torrent payloads, torrent engines, torrent uploads or DRM bypass mechanisms. Already-resolved authorized HTTP media is permitted.
  • The SDK validates resource URLs and rejects obvious prohibited fields. Authors remain responsible for validating redirects, response bodies, authorization and the actual media served.
  • Do not execute remote code or accept arbitrary filesystem paths. Treat addon inputs and upstream metadata as untrusted.

Category handlers

Add the optional categories({ type, after, limit }, { signal }) handler alongside catalogue. Return { categories: [{ id: 'comedy', name: 'Comedy', type: 'movie' }], next: null }. Use stable IDs, a nullable advancing cursor and at most the requested 1 to 200 records. The SDK advertises the category capability and resource only when both category and catalogue handlers exist.

Category IDs are opaque source identifiers up to 256 characters; names are nonempty strings up to 1024 characters. Category types are movie, series, channel and event. The SDK rejects invalid records, repeated IDs within a page and non-advancing cursors.

Your catalogue and search handlers receive optional categoryId. Apply it using authorized source membership and include the selected category object as item.category. Unfiltered items may include their primary category. Never resolve playback to enumerate categories. See the app category contract. Source ingestion and player navigation must also preserve these fields; an advertised endpoint alone does not establish category parity through every downstream adapter.

Player capability metadata

Supply verified codec, resolution and HDR attributes on playback resources so the Boss gateway can filter them against player and library limits. Missing data is unknown; never invent metadata to pass a filter. Strict codec requests reject resources without codec metadata.

The gateway exposes an optional playbackCapabilities extension to apps, described in the player SDK guide. It preserves player limits through native, Xtream and M3U-discovered playback. This author SDK does not advertise that extension automatically: a standalone author-hosted addon must implement its full validation and enforcement before claiming it. The extension is not a promise of universal format compatibility or permission to transcode.

Author acceptance checklist

  1. Fetch /addon.boss with correct and incorrect credentials; verify capability accuracy.
  2. List and search multiple pages without any playback handler calls.
  3. Restart the addon and verify IDs and cursor behavior remain stable.
  4. Ingest it through Boss source type Boss addon; verify movies, series and episodes in native, Xtream and M3U outputs.
  5. Merge it with another source and verify deduplication through reliable identities.
  6. Play real video, verify subtitles and expiry, and ensure text documents or invalid candidates are rejected.
  7. Test disconnect cancellation, missing media, source failure, changed credentials and revoked access.
  8. For apps, test all three SDK discovery modes against the same library and compare canonical IDs and search results.

Passing a metadata fixture is not player certification. Authors and app teams must test real media, seeking and supported platforms.
