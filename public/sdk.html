Protocol v1 / JavaScript reference client

BossTunnel App SDK

Native player integration for combined libraries, remote metadata discovery and on-demand playback.

For app developers: keep your existing Xtream browser and playback integration. Add the optional Boss extension to search authorized sources for titles that are not yet in the downloaded IPTV catalogue.

This is a Boss extension, not standard Xtream behavior. An unmodified IPTV player cannot forward its local search to Boss. Detect the extension first and retain normal Xtream behavior when it is unavailable.

Use an existing Xtream login

The JavaScript module has no dependencies and uses Fetch. It works in modern browsers and Node.js 20+. Download it into the player's codebase and import it locally.

import { BossClient, BossError } from './boss-client.mjs';

// Use the server URL and credentials the user already entered.
const boss = await BossClient.fromXtream(
  xtreamServer, username, password
);

const page = await boss.search('John Q', {
  type: 'movie', skip: 0, limit: 100
});

for (const item of page.items) {
  // item.id: canonical UUID; item.xtreamId: stable numeric ID.
  showSearchResult(item);
}

The server URL includes its configured base path, for example https://bosstunnel.com/xtream. Do not append player_api.php when constructing the SDK client.

Discovery uses POST {server}/boss_api with the existing username and password. No Boss management token is needed. A 404 from a non-Boss server means the extension is unavailable; a 401 means the credentials were rejected.

Connect a native Boss addon or M3U playlist

Building a source addon instead of an app? Use the Addon Author SDK.

// M3U mode: reads only the header, then discovers the Boss API.
const boss = await BossClient.fromM3u(userProvidedPlaylistUrl);
const results = await boss.search('John Q', { type: 'movie' });

// Native mode: the same search, media and playback methods.
const native = await BossClient.fromAddon(userProvidedAddonUrl); // https://host/addon.boss

// File from an input with accept=".boss". Ask the user to trust the host first.
const imported = await BossClient.fromFile(selectedFile, {
  trustedOrigin: "https://your-addon.example",
  token: userProvidedAccessToken
});

Boss playlists contain boss-addon-url=".../addon.boss" on their first #EXTM3U line. The SDK reads at most 8 KB of the header and cancels the remaining download. Missing discovery metadata means ordinary M3U behavior only. Discovery URLs must have the same origin as the playlist.

With a Boss-aware app, all three connection modes expose the same library, canonical IDs, extended search and lazy playback API. Their legacy transport formats are not lossless equivalents: ordinary M3U/Xtream clients still lack remote search, and optional subtitles, guides and archives depend on source capabilities.

const boss = await BossClient.fromAddon(userProvidedAddonUrl);
// For a private author-hosted addon, pass its addon token, never a management token:
// const boss = await BossClient.fromAddon(url, { token: addonAccessToken });
// Native API resources must stay on the configured origin; redirects are rejected.
const page = await boss.catalogue({ type: 'movie', limit: 100 });
const next = page.next
  ? await boss.catalogue({ type: 'movie', after: page.next })
  : null;

Boss-native addon URLs end in /addon.boss. Existing /addon links remain supported. The descriptor declares format: "boss-media-addon", version: 1, capabilities and resource URLs. The wire encoding is UTF-8 JSON; a native Boss addon is not the external compatibility addon format.

A .boss file is a UTF-8 JSON descriptor, not executable code or a video container. File imports accept File/Blob, UTF-8 bytes or text, up to 8 MiB, and require an explicitly trusted origin before sending credentials. Private files contain access links: handle them as secrets. Apps must register their own .boss file picker or operating-system association; the SDK does not register one automatically. Imported files use the same search, metadata and playback methods as hosted links. Do not construct resource paths from assumptions. Follow the descriptor's resource URLs. Unsupported optional resources are omitted.

Catch-up playback

When the descriptor declares catchup, channel records include channel.catchupDays. Call boss.catchup(channel.id, { start, end, signal }) with UTC millisecond timestamps. The same method works through native, Xtream and M3U-discovered SDK connections. The response contains exact upstream playback resources and any required player headers, just like ordinary playback. Native HTTP uses {catchup}?start=...&end=...; the Xtream extension uses action catchup with the same fields.

Intervals must be positive, no longer than 24 hours, and not end more than one minute in the future. The provider must offer that channel and interval within its retained archive window. An advertised window is not a guarantee that every recording exists. Missing, expired or unauthorized archives return 422 at playback. This is provider catch-up, not a Boss recording service or a live timeshift buffer.

Expanded search

  1. Debounce text input and cancel obsolete requests with an AbortController.
  2. Call boss.search(query, { type, skip, limit, signal }). Use 1 to 200 characters.
  3. Merge remote results with local results by canonical id or stable xtreamId, never by title alone.
  4. Use nextOffset for the next search page. Use next only for ordinary catalogue browsing.
  5. On selection, request playback immediately before starting the player.
let pending;
async function searchMovies(query) {
  pending?.abort();
  const controller = pending = new AbortController();
  try {
    const page = await boss.search(query, {
      type: 'movie', skip: 0, limit: 100,
      signal: controller.signal
    });
    if (pending === controller) renderResults(page.items);
  } catch (error) {
    if (error.name !== 'AbortError') showSearchError(error);
  }
}

Search imports metadata into the shared graph. The discovered title can subsequently appear in the same library's Xtream catalogue. It does not start video resolution or guarantee a playable resource exists.

Discovery is bounded: up to 200 records per source page, five pages per catalogue/request and 256 searchable catalogues per source, with a 15-second source deadline and shared queue limits. Feeds are visited in breadth-first rounds, and a failed feed does not prevent other feeds in the source from being searched. Completed feed progress is cached briefly; failed feeds may retry on a later search. Results can be partial when sources fail or the discovery bound is reached. Deep jumps can require subsequent requests. Source relevance ordering is not currently retained. This is not an unlimited global movie search.

Identity and playback

const { media } = await boss.media(item.id);
const { resources } = await boss.playback(item.id);
if (!resources.length) return openSeriesOrSeason(media);

// Resolves an authorized resource when the player requests this URL.
// Choose a resource using the complete picker below; pass its required headers.

Use canonical UUIDs for Boss calls. xtreamId identifies the same item in standard Xtream actions: movie details use vod_id, series details use series_id, and episode playback uses the series route. IDs persist through restarts; never derive them from titles or replace one placeholder item's identity on each search.

Episodes include seriesId, seasonNumber and episodeNumber. The graph preserves external identities independently of the playback source. Multiple authorized sources can attach to one item.

playbackState: "UNRESOLVED" is intentional metadata, not a failed status. A series or season has no direct playback resource. HTTP 422 during playback means no usable resource was provided. Surface this to the user; do not silently retry forever.

BOSS supplies the exact upstream HTTP/HLS URL and required headers. Video flows Provider to Player: BOSS does not fetch video, proxy, relay, remux, transcode or rewrite HLS links. Follow response types and redirects, not URL extensions. Check player capabilities and report unsupported formats instead of expecting Boss to convert them. Universal player certification is not claimed.

HTTP contract

For native mode, use the descriptor's URLs. For Xtream mode, send form-encoded POST requests to {server}/boss_api with username, password, action and action parameters.

ActionParametersResponse

The reference client limits metadata responses to 8 MiB, checking both declared length and streamed decoded bytes. Oversized responses raise BossError with status 413; malformed response objects are rejected. Cancellation while downloading a response remains an AbortError. M3U discovery is limited to 8192 UTF-8 bytes. Page size is 1 to 200. Default is 100. Type values are movie, series, season, episode, channel and event where declared. Do not combine a nonzero cursor and offset.

{
  "items": [{
    "id": "canonical-uuid",
    "xtreamId": 48291,
    "type": "movie",
    "title": "Example title",
    "identities": { "imdb": "tt1234567" },
    "artwork": {},
    "playbackState": "UNRESOLVED"
  }],
  "next": null,
  "nextOffset": null
}

Fields such as year, description, genres, runtimeSeconds, rating, certification and releaseDate may be absent or null. Treat missing metadata as unknown, not as an empty or unavailable library.

Security requirements

  • Use only user-authorized sources and HTTPS in production.
  • Store credentials in the platform's secure credential store. Never request the Boss management token.
  • Treat native addon and playback URLs as private access links. Redact paths, query strings and credentials from logs and crash reports.
  • Do not persist temporary stream URLs indefinitely. Obtain a fresh playback resource when opening a title.
  • Respect capability declarations, expiry and revocation. Do not bypass DRM, subscriptions or authentication.
  • No torrent engines, magnet links, torrent uploads or torrent payload playback. Already-resolved authorized HTTP media is supported.

Player acceptance checklist

  • Boss extension discovery succeeds using existing Xtream credentials; ordinary servers retain normal behavior.
  • A title absent from the downloaded catalogue appears through remote search without a stream request.
  • The same title retains its canonical and Xtream IDs after refresh and restart.
  • Search cancellation does not let older results overwrite newer results.
  • Two sources for one reliable identity appear as one title, with authorized playback fallback.
  • Series/episode navigation preserves identities and does not try to play a series record.
  • Expired links, text-file responses, removed libraries and unavailable sources display actionable errors.
  • Actual media, subtitles, seeking and live playback are verified on every supported player platform.

Boss server contract tests and the reference client are provided. App integration and platform certification must still be performed by the player team.

Player protocol negotiation

When the descriptor advertises playbackNegotiation, call boss.playback(id, { protocols: ['http', 'hls'], signal }) with only protocols your player supports. The same option works through native, Xtream-extension and M3U-discovered connections, and with catchup. Omit it for legacy defaults.

Allowed values are http, hls and dash, where advertised. Empty, duplicate or invalid lists are rejected. Older servers without negotiation support produce an SDK error rather than silently ignoring preferences. The HTTP parameter is boss_protocols, a single comma-separated list preserved on the returned playback URL.

This selects compatible resources; it does not transcode, remove DRM or guarantee codec support. Filename extensions are not container guarantees. Only advertise transports actually supported by the server and player. The current gateway advertises HTTP/HLS playback; do not assume DASH negotiation is available.

Direct playback, no relay

API origin is not playback origin. Keep descriptor API endpoints on the trusted BOSS origin. Returned playback, subtitle and artwork URLs point directly to providers and normally use different domains. Applying the API same-origin restriction to those URLs incorrectly hides available sources.

Provider → Player. BOSS resolves metadata and links, never the video feed. Selected url values preserve the upstream URL, including its path and signature. BOSS does not insert credentials into URLs, probe playback bodies, rewrite HLS playlists or provide a proxy fallback.

import { BossClient, playbackRequest } from './boss-client.mjs';
const boss = await BossClient.fromAddon(privateAddonUrl);
const { resources, failures } = await boss.playback(episodeOrMovieId);
// Render every resource. See the picker example below.

playbackRequest(resource, { supportsHeaders }) validates and returns { url, headers, headerOrigin, referrerPolicy } without downloading anything. Set supportsHeaders only when your media engine enforces origin-scoped headers for redirects and HLS children. The helper cannot configure a player's internals. Without header support it rejects header-dependent resources with 422. Native subtitles and artworkResources use the same direct-resource fields; basic artwork URLs alone cannot transmit headers.

Native .boss, the authenticated Xtream extension and BOSS-aware M3U discovery use this same contract. Ordinary Xtream/M3U players only receive redirects and cannot gain arbitrary request headers or expanded search automatically. If all candidates need headers, standard playback returns 422. Existing protected resource links now redirect or return an explicit unsupported response; they never relay bytes.

After direct handoff BOSS cannot observe upstream HTTP errors, byte counts, seeking or decode success. Implement bounded retry/backoff and let users select another compatible source; request fresh options for expiry. Respect upstream 429 and Retry-After. Do not treat a successful resolution/redirect as successful video playback.

Provider URLs may be IP-bound, region-limited or unreachable from the player's network. Browser playback additionally needs provider CORS and HTTPS support; browser-restricted headers may be impossible to send. Fix provider/player compatibility, not by introducing a hidden BOSS relay. The player must reject non-media responses, torrent payloads and DRM content; BOSS does not inspect direct response bytes.

Secure/permitted resource errors: the protocol supports HTTP and HTTPS provider URLs. The reference helper accepts both; an app may impose a stricter policy. Show blocked-origin or insecure-transport errors per choice, keeping other permitted choices visible, instead of reporting no sources. HTTP permission must be explicit and limited to a user-trusted provider. HTTP can expose provider credentials and media to network observers. Never disable certificate validation, globally allow all origins, or change an upstream URL from HTTP to HTTPS without provider support. An HTTPS Automatic link can redirect to HTTP; the first hop does not secure the provider connection.

Privacy: direct URLs and required headers can contain provider credentials. Use only trusted players and library recipients. Redact complete playback URLs and headers from telemetry, logs and crash reports, disable shared caching and never forward credentials to another origin. Revoking BOSS access prevents new lookups but cannot revoke provider links already issued. Metadata, catalogue and programme-guide requests still pass through BOSS for normalization; media feeds do not.

Complete integration acceptance

  • Discover .boss or the optional Xtream/M3U extension; read capabilities instead of assuming parity with unmodified IPTV players.
  • Display logical categories, page catalogues with next and search with nextOffset. Cancel stale search requests and deduplicate by canonical identity.
  • Fetch series metadata, page episodes by seriesId, preserve season/episode numbers and resolve only the selected episode.
  • Render all quality/source choices and honor advertised codec, height, HDR and language options. Unknown metadata never becomes an invented quality claim.
  • Fetch optional subtitles and header-aware artwork; stream XMLTV, join programme channel IDs to channel.epgId and use declared archive windows for catchup.
  • Verify direct HTTP/HLS, cross-origin credential stripping, range/seek, live, episodes, track selection, subtitles, archives and expiry on each supported platform. Timeshift is not emulated.

Playback source choices

The gateway returns individual compatible streams across all enabled providers. An optional Automatic redirect appears only when a candidate needs no custom headers. Render every entry in resources; using only resources[0] hides the source picker. This works with native Boss, the authenticated Xtream extension and Boss-aware M3U discovery. Standard IPTV players continue to use automatic playback.

const { resources } = await boss.playback(item.id, { signal });
const choices = resources.map(resource => ({
  label: resource.qualityLabel || resource.name || 'Unknown quality',
  tags: resource.tags || [],
  provider: resource.source?.name,
  resource
}));
// playbackRequest validates only; your player must enforce scoped headers.
renderSourcePicker(choices, choice => {
  const request = playbackRequest(choice.resource, {
    supportsHeaders: player.supportsOriginScopedHeaders
  });
  player.open(request.url, { headers: request.headers,
    headerOrigin: request.headerOrigin });
});

Render labels as plain text. Tags can include resolution, codec, HDR, container and audio details. Missing metadata is unknown, not an HD/4K guarantee. Do not persist response-local choice IDs or playback URLs. Selected URLs are exact upstream URLs, not BOSS tickets. expiresAt is UTC milliseconds or null when unknown, never a permanence guarantee. Request fresh options immediately before playback. Automatic selects a redirect-compatible source before handoff; BOSS cannot detect failure or switch providers after redirecting. The player handles bounded retries and alternative choices. Unavailable providers can be listed in failures with generic error codes.

Player capability limits

When descriptor.playbackCapabilities.version === 1, provide the optional capabilities object to playback or catchup. The same options work through native Boss, the Xtream extension and M3U discovery. Omit the object for existing behavior. This extension is separate from transport-protocol negotiation.

const capabilities = {
  codecs: ['h264'], maxHeight: 1080,
  hdr: false, strictCapabilities: true, language: 'en'
};
const { resources } = await boss.playback(item.id, { capabilities, signal });

Boolean wire values are exactly true or false. Duplicate fields, duplicate codecs and malformed values return 400. The SDK checks advertisement and refuses unsupported requests with 422 before sending them. Do not silently remove a player's required limits to get a successful response.

Boss intersects codec lists and height limits with the saved library profile. Either side can prohibit HDR or require known codec metadata. Disjoint codec lists return 422. A supplied language preference overrides the library's default language preference. The API filters choices before returning direct links. Automatic redirect URLs retain player options and recheck the current library policy when redeemed. Already-issued upstream links remain subject to provider access controls, not BOSS revocation. A policy change during resolution returns 409; request fresh playback details.

Limits rely on source-provided metadata. Unknown height or HDR metadata cannot establish compatibility; the player must still handle decode failures. These options do not inspect, remux, transcode or alter media bytes. A legacy IPTV player gains no new behavior unless it implements the Boss extension; direct Boss-hosted Xtream playback URLs also accept these HTTP parameters.

Source categories

Detect capabilities.categories and resources.categories before showing a category browser. This optional v1 extension uses the same category IDs through native Boss, the Xtream extension and M3U-discovered Boss connections. Legacy clients keep their existing behavior.

const groups = await boss.categories({ type: 'movie', limit: 100 });
const nextGroups = groups.next
  ? await boss.categories({ type: 'movie', after: groups.next, limit: 100 })
  : null;
const films = await boss.catalogue({
  type: 'movie', categoryId: groups.categories[0].id, limit: 100
});

Native HTTP follows resources.categories; Xtream-extension POST uses action categories. Supply type movie, series, channel or event. Responses contain categories: [{ id, name, type }] and a nullable next cursor. Page size is 1 to 200. Category IDs are opaque strings for app storage and equal the corresponding Xtream category IDs. Keep category and media cursors separate.

Pass categoryId to catalogue or search. An unfiltered media item includes its primary category; a filtered item includes the selected category. The primary category is not an exhaustive membership list: a merged title remains discoverable in every authorized source category without duplicating its canonical ID. Other-source labels use Source Name | Category. Category 1, Boss Media, contains uncategorized items only. Omit categoryId to browse all items. Removed or unrelated source categories do not expose their titles.

Older players can ignore the new fields. Player integrations must explicitly consume this resource and preserve category assignments; updating the server alone does not add category navigation to an installed app.

WebDAV libraries

A configured WebDAV source becomes the same canonical catalogue used by other Boss sources. Apps use the normal catalogue, search, media, playback and subtitle methods; they do not implement WebDAV catalogue discovery themselves. Direct playback may expose provider Authorization headers to the trusted player. Header-dependent WebDAV resources need a header-aware player; ordinary redirect-only IPTV playback returns 422.

const shows = await boss.catalogue({ type: 'series', limit: 100 });
const episodes = await boss.catalogue({
  type: 'episode', seriesId: shows.items[0].id, limit: 100
});
const details = await boss.media(episodes.items[0].id);
const playback = await boss.playback(episodes.items[0].id);
const captions = await boss.subtitles(episodes.items[0].id);

Follow pagination for both series and episodes. Playback resources carry exact upstream URLs and required headers. The player fetches original bytes directly from the WebDAV server. MP4, MKV and other supported containers are not converted. Range requests and seeking depend on the source and player. Optional codec limits require trustworthy source metadata.

Boss scans folders in the background, identifies common season/episode filenames and reads local NFO metadata, artwork and matching SRT/VTT/ASS/SSA files. IMDb/TMDB/TVDB IDs in filenames, folders or NFOs support reliable identity merging. Missing metadata may be enriched on a detail request using the existing metadata provider; ambiguous or unidentified names remain local rather than being guessed. Only files actually discovered on WebDAV become playable episode records.

Native Boss, authenticated Xtream extension and M3U-discovered Boss connections share these APIs. Ordinary Xtream clients browse VOD and series/season/episode lists; ordinary M3U clients receive file entries and groups. External subtitle discovery and expanded search require the Boss extension or another output protocol that supports them. WebDAV file libraries do not advertise live television, EPG, catch-up or timeshift.

Connection authentication supports Basic username/password, Bearer access token, or anonymous access. Use HTTPS. Initial listing takes time; a completed catalogue is not a guarantee that every file is online or decodable. Stable file paths retain their IDs across rescans/restarts; renamed files require reliable identities to merge with the old title. Multi-episode files can appear as multiple episodes but play the original complete file without invented chapter offsets.

Live programme guide

Check descriptor.capabilities.epg and descriptor.resources.guide. When present, boss.guide({ signal }) returns a Fetch Response containing XMLTV. Stream response.body into the app's XMLTV parser and persistent guide database; do not load a large merged guide into one in-memory array. Close or cancel the body when finished.

if (boss.descriptor.capabilities.epg) {
  const response = await boss.guide({ signal });
  await programmeDatabase.importXmltv(response.body, { signal });
}
// Match XMLTV programme/@channel to the channel record's channel.epgId.
// programmeDatabase is supplied by the app, not the Boss SDK.

The same method works for native .boss files/links, Boss-aware M3U discovery and Xtream SDK connections. Native mode uses the advertised guide URL; Xtream mode sends credentials in a POST body to {server}/xmltv.php. Ordinary M3U clients use x-tvg-url; ordinary Xtream clients use XMLTV or their short-guide API. Channel IDs remain stable across outputs and restarts. XMLTV timestamps include a UTC offset; convert them for the viewer's timezone.

Guides are merged only from the library's enabled, authorized sources. Xtream sources automatically check their authenticated default XMLTV endpoint. M3U sources discover x-tvg-url or url-tvg in the playlist header. An explicitly configured XMLTV URL takes precedence. Missing or denied provider guides do not become invented programme data. Movies, series and WebDAV file libraries have metadata, not live schedules. Rendering now/next and the guide grid remains the app's responsibility.

Developer MCP

Connect an MCP-compatible coding agent to https://bosstunnel.com/mcp using Streamable HTTP. No BOSS account, source password or administration token is required. This read-only service exposes the public protocol specification, app SDK, addon SDK and examples.

import { Client } from '@modelcontextprotocol/sdk/client/index.js';
import { StreamableHTTPClientTransport }
  from '@modelcontextprotocol/sdk/client/streamableHttp.js';

const client = new Client({ name: 'boss-integration', version: '1.0.0' });
try {
  await client.connect(new StreamableHTTPClientTransport(
    new URL('https://bosstunnel.com/mcp')
  ));
  const docs = await client.callTool({
    name: 'boss_docs', arguments: { document: 'protocol' }
  });
  // Follow nextOffset to read the complete document.
} finally {
  await client.close();
}

Agents can also read boss://docs/protocol resources and request the integrate_boss prompt with target app or addon. The service cannot search customer libraries, modify accounts, execute code, fetch submitted URLs or verify media playback. Do not submit private addon links, credentials or personal data.

Use client-managed MCP initialization. Request bodies are limited to 32 KiB; the endpoint allows 16 concurrent requests and 600 requests per minute globally. Respect HTTP 429 and Retry-After. Only same-origin browser requests are accepted; server-side agents can connect without an Origin header. The human-readable guide is this page, not the protocol endpoint.
